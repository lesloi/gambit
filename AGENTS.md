# Gambit

Gambit is a personal chess training PWA: puzzles, tactical motifs, endgames, a curated opening
repertoire and games against the engine. Vocabulary: [GLOSSARY.md](./GLOSSARY.md).

## Architecture

- `src/app`: the shell. `src/features/*`: one folder per mode. `src/ui`: shared components.
- Vite + React + TypeScript, styled with Tailwind from the tokens in `src/styles/index.css`.
- **No backend and no account.** The app is a static build; `nginx.conf` serves it and the image
  holds nothing else. Never add a runtime server: the backup is an exported file
  ([DECISIONS.md](./docs/DECISIONS.md#persistence)).
- Progression lives in IndexedDB. `src/db` holds the schema; the `reviews` journal is the source
  of truth and FSRS state is derived from it.
- Content is baked into the image (`content/`, generated by `scripts/`), never fetched at runtime.
- Stockfish runs in a Web Worker. It stays single-threaded, so the app needs no COOP/COEP headers.
- The app makes **no network request at runtime**. Adding one needs the owner's agreement, and the
  CSP must name the host.

## Decisions

[DECISIONS.md](./docs/DECISIONS.md) holds the lasting choices and their reasons, by theme. Read
the section of the subject you touch. A decision can be questioned: if it no longer holds, say so,
propose an alternative with your arguments, and rewrite the entry once the owner agrees. Add an
entry only for a choice that is costly to reverse and whose reason the code does not show.

## Working

- After a change: `pnpm check`, then `pnpm test` and `pnpm build` for what you touched.
- Tests come first: write the failing test, then the minimum code, then refactor. A test follows
  Arrange–Act–Assert and is named by the behaviour it protects.
- Do not write unit tests for design or layout; a flow gets an end-to-end test later.
- Branches: `type/short-description` (`feature`, `bugfix`, `hotfix`, `release`, `chore`).
  Commits: Conventional Commits under 72 characters, without `Co-authored-by:`.
- Never push, open a pull request or deploy without the owner's go-ahead.
- Update the docs only when a rule, a convention or a command changes, not for a new feature.
- Never commit a secret. The kubeconfig lives in the `KUBECONFIG` GitHub secret.

## Privacy

**Nothing about the user leaves the device.** There is no analytics, no cookie, no account and no
server log of the user. A feature that would send anything needs the owner's agreement first; the
README and [DECISIONS.md](./docs/DECISIONS.md) must name the third party.

## Issues

- GitHub Issues on `lesloi/gambit`. Labels: the area (`web`, `content`, `engine`, `infra`, `ci`,
  `documentation`, `dependencies`), the kind (`bug`, `enhancement`), and `accessibility` for a
  barrier that crosses several areas.
- To change an issue, edit its description rather than adding a comment; keep comments for a
  discussion.
- Declare a dependency with GitHub's relations (`--blocked-by`, `--blocking`, `--parent`), not in
  the text.
